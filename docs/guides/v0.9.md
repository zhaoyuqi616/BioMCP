# v0.9 evidence interpretation

This release adds claim-level provenance and interpretation, a question-based explorer with source and subject filtering, and separate drug candidate and regulatory lookup records.

## Validation

Run `python scripts/check.py` and `python scripts/browser_smoke.py` in the development environment with the browser extra installed. Regression cases preserve disputed ClinGen findings alongside positive association scores, retain unknown provenance explicitly, prevent drug-level approval from becoming target-specific approval, and test source/question/text filtering. Browser validation searches TP53, filters tissue records to kidney, opens the supporting record, refreshes a section and downloads FASTA using deterministic providers.

## Scientific scope

No universal confidence score is computed. Disease equivalence and conflict resolution are not inferred from names. Original source records remain separate. Mechanisms, directness and disease-specific drug indications are not newly retrieved in this release; the interface explicitly exposes those gaps. Dataset releases are retained when supplied, otherwise marked unknown. Retrieval timestamps are not database publication dates. A failed or unchecked regulatory lookup cannot support a negative approval conclusion.

## Compatibility

The evidence v1 schema gains additive interpretation fields and regulatory records. Consumers should tolerate new record kinds. The pilot deployment requirements and limitations remain as documented in the [v0.8 guide](v0.8.md).
