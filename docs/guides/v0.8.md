# BioMCP v0.8 release and deployment guide

## Changes

| Direction | Delivered behavior |
|---|---|
| Evidence quality | FDA results distinguish `approval_record_found`, `no_exact_match`, `lookup_failed` and `not_checked`. Coverage reports each outcome, and failed lookups produce partial coverage. An approval record requires an exact ingredient or generic-name match, an approval submission and an application identifier. |
| Scientific regressions | Deterministic tests cover SPP1 archive fallback, TSP1 resolution, HPA zero versus missing expression, exact drug matching, provider failures and source attribution. |
| Reliability | Dashboard searches and `gene_evidence` share a 45-second operation deadline and 24 outbound attempts across core retrieval and enrichment. Core results stream first in the dashboard. Provider attempts and HTTP outcomes are counted without query or token labels. Redis cooldown persistence has an executable cross-process restart drill. |
| Pilot and releases | An optional bearer-token API checks issuer, audience, signature, expiry, token scope and current subject grants. API exports have owner checks, one-hour expiry and a 20-export per-user cap. Dependencies are locked, and CI includes browser and Redis drills. |

An FDA drug approval record does not establish approval for a particular gene or indication. No exact match means the bounded lookup found no exact record. Failed and unchecked lookups cannot support a negative conclusion.

## Reproducible validation

```bash
python -m pip install uv==0.13.7
uv sync --frozen --extra dev --extra pilot --extra browser
uv run --frozen python scripts/check.py
uv run --frozen python tutorials/validate_mcp.py --output /tmp/biomcp-validation.json
uv run --frozen playwright install chromium
uv run --frozen python scripts/browser_smoke.py
uv run --frozen python scripts/redis_drill.py --redis-server /absolute/path/to/redis-server
```

The browser test launches a temporary authenticated dashboard with deterministic provider fixtures, searches TP53, opens the explorer, refreshes a section and verifies a FASTA download. Set `BIOMCP_CHROME` to an installed Chrome executable if preferred. The Redis drill starts its own isolated Unix-socket instance with AOF persistence and checks cooldown retention after a graceful restart. It does not test crash recovery, failover or storage loss.

The deterministic suite does not certify live scientific database contents. Run the validation tutorial's live check separately and review provider failures explicitly.

## Experimental single-organization API

The pilot is separate from the local Gradio dashboard and MCP transports. It currently serves public research only. It is not a private-database authorization implementation.

Install the `pilot` extra. Configure a trusted organization issuer, API audience, fixed HTTPS JWKS URL, Redis connection, protected grants file and writable export database path.

```bash
export BIOMCP_ISSUER='https://your-identity-provider.example/'
export BIOMCP_AUDIENCE='biomcp-pilot'
export BIOMCP_JWKS_URL='https://your-identity-provider.example/.well-known/jwks.json'
export BIOMCP_GRANTS='/absolute/private/path/grants.json'
export BIOMCP_EXPORT_DB='/absolute/private/path/exports.db'
export BIOMCP_REDIS_URL='redis://127.0.0.1:6379/0'
uv run --frozen uvicorn ensembl_uniprot_mcp.pilot:create_app --factory --host 127.0.0.1 --port 8000
```

Replace the example identity-provider values. Protect the grants and database directory with OS permissions. Redis must be private and authenticated or TLS-protected where appropriate. Keep the existing runtime profile at its default local value. The new API provides its own authentication boundary and does not enable other hosted transports.

Example grants file, using the provider's stable subject identifier as the key

```json
{"organization-subject-id": ["research:public", "export:write", "export:read"]}
```

Requests need an RS256 access token containing matching `iss`, `aud`, `sub`, `exp` and a space-separated `scope` claim. Both token scopes and current grants must allow the operation. Removing a grant blocks subsequent requests, including downloads.

| Endpoint | Required scope | Behavior |
|---|---|---|
| `GET /evidence/{query}` | `research:public` | Single-gene evidence snapshot |
| `POST /exports` | `export:write` | Stores caller-supplied report text, bounded to 262144 characters |
| `GET /exports/{id}` | `export:read` | Owner-only download while unexpired, with `no-store` caching |
| `GET /operations` | `operations:read` | Process-local outbound counters |

Expired exports are inaccessible immediately and deleted by a periodic sweep or the next export creation. They may persist in storage backups under the operator's retention policy. The API export mechanism does not replace local Gradio FASTA downloads.

## Deployment acceptance gates

Before exposing the pilot, validate real issuer integration, expired and wrong-audience tokens, key rotation, grant revocation, cross-user export denial and Redis outage behavior. Configure TLS termination, ingress request-size and rate limits, restrictive filesystem permissions, backup retention and operational alerts. Metrics reset on process restart and require external collection for long-term monitoring. Hosted dashboard identity, private data, durable jobs and organization-wide audit retention remain future work.

The 45-second budget covers dashboard searches and `gene_evidence`. Legacy tools and standalone refreshes retain their existing provider-level limits. Large operations may return partial evidence when their attempt budget is exhausted.

## Release and rollback

CI installs from `uv.lock` across Python 3.10–3.13 and runs deterministic validation. Python 3.11 additionally runs Chromium and Redis drills. The Dockerfile uses the lock and a non-root runtime user for the stdio server. A successful container build and deployment smoke test are still required in a Docker-capable environment. The base image is not digest-pinned.

Deploy an immutable commit or image tag, preserve the previous artifact, and snapshot the export database before upgrades. To roll back, stop the new API, restore the previous artifact and its compatible database snapshot, then repeat authentication and evidence smoke checks. The preceding local-dashboard commit is `2738a2b`; it has no pilot API, so rolling back to it requires disabling the pilot ingress. Do not reuse a newer database with an older release without checking schema compatibility.
